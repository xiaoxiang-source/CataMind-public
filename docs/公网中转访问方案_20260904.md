# 催化智构 CataMind · 腾讯云公网中转访问方案（本地不出网、仅主动出站）

| 项目 | 内容 |
|---|---|
| **文档版本** | v1.0 |
| **更新日期** | 2026-09-04 |
| **已确认前提** | 本地为**纯私有 NAT**（本机 `192.0.2.10/16`，无公网入站）｜ **已有备案域名** ｜ 外部访问者 **1–3 人（本人异地为主）** ｜ 隧道组件选用 **frp** |
| **平台事实** | Rocky Linux 9.8；平台仅监听 `127.0.0.1:8000`（HTTP）；前端 `API_BASE=''` 固定同源，公网必须经 Nginx/frp 转发 |
| **目标** | 外部用户经 `https://<域名>` 访问本地平台；**本地不暴露任何公网入站端口**；云服务器仅做加密中转 |

---

## 1. 方案结论（TL;DR）

- 在**腾讯云**部署 `frps`（服务端）+ **Nginx**（TLS 终结 + 访问控制 + 限速）；在**本地**部署 `frpc`（客户端），由 frpc **主动出站**连接云上 `frps:7000`，建立加密隧道。
- 云上 `frps` 仅把平台映射到**云本机回环 `127.0.0.1:7001`**，再由 Nginx `https://<域名>` 反代——**云上也不对公网开放业务端口**（公网只见 80/443）。
- 外部用户 → 云（HTTPS）→ frps（TLS 隧道）→ 本地 frpc → `127.0.0.1:8000` 平台。
- 本地**无需固定公网 IP、无需端口映射**；出口 IP 变化不影响（frp 每次启动主动连出，鉴权靠共享密钥而非 IP）。
- 上线安全底线：平台本地账号密码鉴权必须保持启用（`CATMAT_AUTH_ENABLED=1`、`CATMAT_LOCAL_AUTH_ENABLED=1`）；Nginx Basic Auth 可选作额外纵深防护。

```
                         ┌────────────── 腾讯云（公网入口，仅 80/443 对公网）──────────────┐
外部用户(1-3人) ──HTTPS──▶ │ Nginx :443 (TLS终结 + Basic Auth + limit_req)                  │
  浏览器                    │   │ proxy_pass http://127.0.0.1:7001                          │
                           │   ▼                                                           │
                           │ frps :7001  ◀─(仅回环监听, 不对公网)─ 被代理端口                │
                           │ frps :7000  ◀──(frp 控制/数据, TLS 加密, token 鉴权)──────┐    │
                           └───────────────────────────────────────────────────────────┼────┘
                                                                                         │ 主动出站
                                                                               ┌─────────┼──────────┐
                                                                               │ 本地服务器(Rocky 9)   │
                                                                               │ frpc (systemd 守护)    │
                                                                               │   │ http://127.0.0.1:8000
                                                                               │ catmat.py serve         │
                                                                               └──────────────────────────┘
```

## 2. 整体网络架构

| 层 | 位置 | 角色 | 监听/暴露 |
|---|---|---|---|
| 入口层 | 腾讯云 | Nginx `:80/443` | **对公网开放 80/443**；TLS 终止、Basic Auth、限速、日志 |
| 中转层 | 腾讯云 | frps | `:7000`（frpc 连入，承载控制+数据，TLS+token）；`:7001`（`proxyBindAddr=127.0.0.1`，仅供 Nginx 反代，**不对公网**） |
| 隧道客户端 | 本地 | frpc | **仅主动出站**连云 `:7000`，本机无新增入站监听 |
| 业务层 | 本地 | `catmat.py serve :8000` | 仅 `127.0.0.1:8000` 回环可达，由本机 frpc 转发 |

- 公网访问者看到的是一个普通 HTTPS 站点（域名 + 443），无法感知后端是隧道。
- 云服务器**不落盘业务数据**：catmat.db、用户上传文件全部留在本地，云仅做字节转发（隧道内加密，Nginx 层只见密文 + TLS 明文包头）。

## 3. 请求与流量转发路径（一次页面加载的完整链路）

```
1) 用户浏览器  https://catmat.example.com/            TLS(1.2+) 握手 → Nginx
2) Nginx       Basic Auth 校验(过渡期) → 401/放行       (平台自身登录启用后可去掉)
3) Nginx       proxy_pass http://127.0.0.1:7001        Host: catmat.example.com
4) frps        命中"平台"代理 → 经加密隧道下推给本地 frpc
5) frpc        转成 http://127.0.0.1:8000/ 请求本地平台   (回环明文, 不跨网卡)
6) catmat.py serve 返回 HTML/JSON → 沿原路回传
```

- **同源策略天然满足**：页面与 `/api/*` 都经同一域名+443，前端 `API_BASE=''`（同源）无需改动。
- 隧道内 Nginx 传的是 `Host` 头保留（`proxy_set_header Host $host`），frps 若配多代理可按域名分流（本方案单域名用 TCP 类型代理，无需 vhost 路由）。
- 长连接（页面轮询、ML 训练轮询）每请求独立 HTTP，无 WebSocket 依赖，Nginx `proxy_read_timeout` 设 300s 兜底即可。

## 4. 本地主动建立连接的机制（核心原理）

- frpc 以**客户端身份**向云 frps 发起 TCP（`7000`），连接建立后 frp 在其上多路复用：**一条控制连接**负责注册/心跳，**每个被代理的 TCP 流量动态复用同一 TCP 连接池**（frp ≥0.52 默认 stream 模式）。
- frpc 配置里写死**云服务器地址**（域名或 IP），因此**本地出口 IP 是否固定、是否 CGNAT 均不影响**——方向始终是"本地 → 云"。
- 鉴权：`auth.method=token`，两端共享强随机 token（≥32 字符）。云上如做 IP 白名单会因本地出口变化而失效，**本方案以强 token 为主、不做 IP 白名单**（监控兜底见 §11）。
- 保活与重连：frp 内置心跳（`transport.heartbeatInterval=10` / `heartbeatTimeout=90`）；连接断开后按退避自动重连（默认 3s 起）。另加 systemd `Restart=always` 兜底进程级崩溃（§10）。

## 5. 所需服务与配置项（含示例文件）

> 版本：frp **v0.61+**（TOML 配置；若装旧版 .ini 语法需迁移）。下载：GitHub fatedier/frp releases，选 `linux_amd64`（云/本地均为 x86_64 时）。

### 5.1 云服务器（腾讯云 Ubuntu 22.04 或与本地异构均可）

**A. frps** —— `/etc/frp/frps.toml`

```toml
bindAddr = "0.0.0.0"          # frpc 需连入，故监听所有（安全由 token+TLS+防火墙兜底）
bindPort = 7000

auth.method = "token"
auth.token = "REPLACE_WITH_64_HEX_RANDOM"   # 强随机；本地 frpc 同一份

transport.tls.force = true    # 强制隧道加密（frpc 未开 TLS 将拒绝连接）

# 被代理端口只允许回环访问 → 公网无法直连 7001，只有本机 Nginx 能到
proxyBindAddr = "127.0.0.1"
# proxyBindPort 由各 proxy 的 remotePort 决定，无需全局

log.to = "/var/log/frp/frps.log"
log.level = "info"
log.maxDays = 7
```

**B. systemd** —— `/etc/systemd/system/frps.service`

```ini
[Unit]
Description=frp server (CataMind relay)
After=network.target nginx.service

[Service]
ExecStart=/usr/local/bin/frps -c /etc/frp/frps.toml
Restart=always
RestartSec=3
LimitNOFILE=65536

[Install]
WantedBy=multi-user.target
```

**C. Nginx** —— `/etc/nginx/sites-available/catmat-tunnel`（可选 Basic Auth 纵深防护）

```nginx
# 1) 80 → 443
server {
    listen 80;
    server_name catmat.example.com;
    return 301 https://$host$request_uri;
}

# 2) HTTPS
server {
    listen 443 ssl http2;
    server_name catmat.example.com;

    ssl_certificate     /etc/letsencrypt/live/catmat.example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/catmat.example.com/privkey.pem;
    add_header Strict-Transport-Security "max-age=31536000" always;

    client_max_body_size 50m;                       # 结构文件/数据集上传
    proxy_read_timeout 300s;                        # ML 训练等长请求兜底

    # —— 过渡期访问控制（平台自身登录实现后删除以下 2 行）——
    auth_basic "CataMind 异地访问";
    auth_basic_user_file /etc/nginx/.htpasswd_catmat;

    # —— 低频限速（1-3 人场景足够）——
    limit_req_zone $binary_remote_addr zone=catmat:10m rate=10r/s;
    limit_req zone=catmat burst=20 nodelay;

    location / {
        proxy_pass http://127.0.0.1:7001;           # → frps → 隧道 → 本地 8000
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

### 5.2 本地服务器（Rocky 9）

**A. frpc** —— `/etc/frp/frpc.toml`

```toml
serverAddr = "catmat.example.com"   # 建议用域名：云 IP 变更时本地零改动
serverPort = 7000

auth.method = "token"
auth.token = "REPLACE_WITH_64_HEX_RANDOM"    # 与 frps 完全一致

transport.tls.enable = true        # 与 frps tls.force 对应
transport.heartbeatInterval = 10
transport.heartbeatTimeout = 90

log.to = "/var/log/frp/frpc.log"
log.level = "info"

[[proxies]]
name = "catmat-platform"
type = "tcp"
localIP = "127.0.0.1"
localPort = 8000
remotePort = 7001                  # 云上回环监听（见 frps proxyBindAddr）
```

**B. systemd** —— `/etc/systemd/system/frpc.service`

```ini
[Unit]
Description=frp client -> Tencent relay (CataMind)
After=network-online.target catmat.service
Wants=network-online.target

[Service]
ExecStart=/usr/local/bin/frpc -c /etc/frp/frpc.toml
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
```

> `After=catmat.service`：本地平台先起再起隧道，避免隧道通而业务未就绪；平台崩溃重启也不影响 frpc（隧道目标仍指向 8000，待平台恢复即通）。

### 5.3 平台侧配置

- 平台应以 `python3 catmat.py serve --host 127.0.0.1 --port 8000` 启动；前端固定使用同源 API。
- 建议把 `.env` 中 `CATMAT_DEFAULT_NPROC` 等按需保留；公网访问者的只读/低权限需求由 Basic Auth + 平台登录承担。

## 6. 域名及证书配置

1. **DNS**：DNSPod 添加 A 记录 `catmat.example.com → 腾讯云服务器IP`（TTL 600）。如本地 frpc 的 `serverAddr` 用域名，云 IP 变更时只需改 DNS，本地免改。
2. **证书**：推荐 Let's Encrypt（certbot 自动续期，`certbot --nginx -d catmat.example.com`）或腾讯云免费 SSL（控制台申请 → Nginx 版上传）。
3. **有效期与续期**：certbot 自带 timer；用 `certbot renew --dry-run` 验证。证书**只在云上**（Nginx），frp 隧道用自管 TLS 证书或 `tls.force`（frp 内置自签亦可，本方案 token 鉴权已覆盖身份，隧道证书仅防窃听，frp 默认即加密）。
4. **备案**：域名已完成 ICP 备案才能在大陆地域 80/443 公开服务；页面按监管要求展示备案号。

## 7. 身份认证与访问控制（纵深三层）

| 层 | 机制 | 状态 | 说明 |
|---|---|---|---|
| ① 传输/入口 | Nginx **Basic Auth** | **本期必开** | 因为平台自身登录后端未实现；单账号（本人）或按需 htpasswd 加人。密码强随机，仅本人/授权者持有 |
| ② 应用层 | 平台自身登录（双路径） | 待后端实现后启用 | 实现 `CATMAT_AUTH_ENABLED=1` 后，可删除 Basic Auth 两行并切换为平台登录（管理员/用户双路径见 `auth-security-design.md`） |
| ③ 隧道层 | frp token | 开启 | 防止他人伪造 frpc 抢占隧道；**不做 IP 白名单**（本地出口可能变化） |

- 1–3 人规模建议：入口 Basic Auth 一个共享账号 + 平台管理员令牌双保险；若后续多人访问，逐人发 htpasswd 账号或直接启用平台登录。
- 后续若仅限特定用户，Nginx 可再加 `allow/deny` 或 fail2ban（§11）。

## 8. 防火墙策略

### 云服务器（腾讯云安全组 + ufw）

| 端口 | 是否对外 | 说明 |
|---|---|---|
| 22 | 仅管理员 IP | SSH（建议来源限定本人 IP 段） |
| 80/443 | **对公网** | Nginx 入口 |
| 7000 | **对本地出口可达** | frps 控制/数据口。若本地出口 IP 稳定可设来源白名单；不稳定则对公网开放，但**强 token 兜底 + 日志监控**。可另用 frps `allowPorts` 限制 |
| 7001 | **不对外** | frps `proxyBindAddr=127.0.0.1`，仅回环，Nginx 直连 |

```bash
sudo ufw allow 22/tcp && sudo ufw allow 80/tcp && sudo ufw allow 443/tcp
sudo ufw allow 7000/tcp        # 仅此口给 frpc；7001 无需放行（回环）
sudo ufw enable
```

### 本地服务器

- **入方向**：维持现状（8000 仅内网可达）；不要为 8000 增加任何公网映射。
- **出方向**：放行到云 IP/域名的 7000（一般出方向默认放行即可）。建议仅允许目标 `catmat.example.com:7000` 出站（firewalld `--add-rich-rule`），最大限度收敛横向面。

## 9. 数据传输安全

| 段 | 保护 | 备注 |
|---|---|---|
| 外部用户 ↔ 云 Nginx | HTTPS/TLS 1.2+（证书） | HSTS 头已加；浏览器地址栏锁形标识 |
| 云 frps ↔ 本地 frpc | frp `transport.tls.force=true` 加密 | 云→本地数据不落盘；防云侧被嗅探（即便云被攻破，历史流量不可读） |
| 本地 frpc ↔ `catmat.py serve` | 回环明文 | 仅本机回环内传输，风险较低；如需可在本地另加自签 TLS（本期不做） |

- 敏感操作（登录口令、上传结构）全程加密：外部段 HTTPS、隧道段 frp TLS。
- 平台上传大文件（结构文件/数据集）同样经隧道，受 §12 带宽与 `client_max_body_size` 约束。

## 10. 断线重连与可用性

| 环节 | 机制 |
|---|---|
| frpc 断开 | frp 内置心跳 + 自动重连（指数退避） |
| frpc 进程崩溃 | systemd `Restart=always`（5s） |
| 本地平台重启 | frpc 存活、隧道仍在，平台恢复即通（`After=catmat.service` 只影响首次启动顺序） |
| 云 frps/nginx 重启 | systemd 托管自动拉起；本地 frpc 会自动重新连入 |
| 网络闪断（校园网/VPN） | frp 心跳超时后重连；建议本地出口稳定后验证一次 |

**验收**：`systemctl stop frpc` → 5s 内自动重启并连上；拔本地网线再插 → 隧道自动恢复（观察 `/var/log/frp/frpc.log` 重连记录）。

## 11. 日志监控与告警

| 日志 | 路径/方法 | 关注点 |
|---|---|---|
| frps | 云 `/var/log/frp/frps.log` | 新客户端连入告警、异常断开 |
| frpc | 本地 `/var/log/frp/frpc.log` | 重连频率（频繁=网络不稳） |
| Nginx | 云 access/error log | 401 次数（爆破探测）、4xx/5xx 比例 |
| 平台 | 本地 `logs/server.log` + `audit` 表 | 异常 traceback、关键操作审计 |

**建议告警**（1-3 人规模，可用 cron 探活脚本 + 邮件/企微通知）：
- 隧道探活：cron 每 5 分钟 `curl -sk https://catmat.example.com/api/health` 失败即告警。
- 登录爆破：Nginx error log 按 IP 统计 401，配合 fail2ban（`nginx-http-auth` jail）自动封禁。
- frps 陌生 token 重试：grep frps.log 的 `auth` 失败计数。

## 12. 性能与带宽限制

- **流量特征**：页面/JSON API 为主，单请求 KB 级；平台 5s 轮询很轻（metrics 仅 ~1–3 KB/次）；重负载主要是结构文件上传、图表下载、PDOS 文件查看（数十 KB–数 MB）。
- **1–3 人预估**：并发极低，家庭/校园上行 ≥10 Mbps 即可流畅；瓶颈通常在**本地出口上行带宽**，不在云。
- **可配置限速**：
  - frps `transport.bandwidthLimit`（整机限速，单位 MB/s）；
  - Nginx `limit_req`（已示例 10 r/s burst 20）防刷。
- **上传限制**：`client_max_body_size 50m` 与平台一致；如常有超大文件，建议走对象存储直传（后续演进，不在本期）。

## 13. 故障排查（症状 → 命令 → 结论）

| 症状 | 排查 | 常见根因 |
|---|---|---|
| 域名打不开 | `curl -I https://catmat.example.com`；云 `systemctl status nginx frps` | 证书过期 / nginx 未 reload / 安全组未放 443 |
| 页面 502 | 云 `curl -s http://127.0.0.1:7001/api/health`（绕隧道直达 frps）；frpc `./frpc status -c ...` | frpc 未连上（token 不一致/云 7000 不通）/ 本地平台未启动 |
| 登录被拒 | 云 `tail /var/log/nginx/error.log` | Basic Auth 密码错 / htpasswd 文件路径错 |
| 频繁断开重连 | 本地 `tail /var/log/frp/frpc.log`；`ping 云IP` | 本地出口不稳 / 心跳超时参数过小 / 云侧限流 |
| 隧道通但慢 | 本地 `iperf3` 或大文件上传测速 | 本地上行带宽不足（瓶颈在本地出口） |
| 怀疑被爆破 | `grep -c "auth" /var/log/frp/frps.log`；Nginx 401 计数 | 及时换 token / 加 IP 白名单 / fail2ban |

**本地侧快速自检（先于云排查）**：
```bash
curl -s http://127.0.0.1:8000/api/health        # 平台活着？
systemctl status frpc && tail -20 /var/log/frp/frpc.log
```

## 14. 方案对比（frp vs 其它）

| 方案 | 安全性 | 稳定性 | 维护成本 | 适用场景 | 说明 |
|---|---|---|---|---|---|
| **frp**（本方案） | 高：token+TLS+仅 80/443 暴露 | 高：成熟、重连机制完善 | 中低：两端各一个二进制+systemd | **本人异地 / 课题组远程访问 HTTPS 站点** | 生态成熟、文档多、可限速；推荐 |
| **SSH 反向隧道 + autossh** | 高（走 SSH 加密） | 中：多路复用差、长连接易被 NAT 掐断 | 低：零新增组件 | 应急、临时、单连接 | 复用系统 ssh；无内置限速/多代理管理；运维要写脚本 |
| **rathole**（轻量） | 高：支持 TLS | 高 | 低：单二进制 | 极低资源场景 | 生态小、排查资料少 |
| **WireGuard 组网（云作 relay + Nginx）** | 最高（内网级加密，云仅转发） | 高 | 中高：需管理密钥/peer/路由 | 未来把本地并入"云内网"做更多服务 | 若仅暴露一个 HTTP 站，frp 更省事；WG 更适合多服务/多客户端统一接入 |
| **纯端口映射（路由器/NAT）** | 低：直接暴露 8000 原端口 | 依赖公网 IP | 最低 | **不适用**：本地纯 NAT 无公网 IP，且用户明确要求本地不暴露端口 | 排除 |
| **Cloudflare Tunnel** | 高 | 高 | 低 | 有 CF 域名 | 用户指定腾讯云中转，故不采用（可作替代） |

**结论**：按已确认条件（纯 NAT + 备案域名 + 1-3 人 + 零依赖平台），**frp 为最优解**；未来若需多服务统一接入或多人组网，可平滑升级为 WireGuard。

## 15. 部署分步清单（前置条件 + 风险点）

> 前置：云服务器（Ubuntu，已开安全组 22/80/443/7000）、域名已解析并备案、本地可出站访问云 7000。

| # | 步骤 | 操作要点 | 前置条件 | 风险点 |
|---|---|---|---|---|
| 1 | 云装 frps | 下载 frp → `/usr/local/bin/frps` + `/etc/frp/frps.toml` + systemd | root/`sudo` | 版本选 v0.61+（TOML）避免旧语法 |
| 2 | 云配 Nginx | 站点文件 + certbot 证书 + htpasswd | 域名解析生效 | 证书签发前不要开 443 抢占；Basic Auth 忘开会直接裸奔 |
| 3 | 生成强 token | `openssl rand -hex 32` → 写入两端 | — | token 写错=隧道静默不通，先本地验证 |
| 4 | 本地装 frpc | frpc.toml + systemd（`After=catmat.service`） | 本地 root/`sudo` | serverAddr 建议用域名，云 IP 变更免改 |
| 5 | 通联验证 | 云 `curl http://127.0.0.1:7001/api/health` | frps/frpc 均运行 | 若 502 先查 frpc 日志 token/端口 |
| 6 | 公网验证 | 手机流量访问 `https://catmat.example.com` | 云安全组 443 | 若不通，查安全组/ufw/域名解析 |
| 7 | 加固 | 关闭密码 SSH、fail2ban、探活 cron、frps 日志审查 | 步骤 6 通过 | 勿把 7000 对全网后仍用弱 token |
| 8 | 演练断线 | `systemctl restart catmat` 与拔网线各一次 | 步骤 6 通过 | 确认自动恢复时间在可接受范围 |

## 16. 演进方向（可选，不阻塞上线）

1. **平台自身登录已启用**：生产保持 `CATMAT_AUTH_ENABLED=1` 与 `CATMAT_LOCAL_AUTH_ENABLED=1`；管理员和普通用户统一使用本地账号密码，后端按角色集中授权。Nginx Basic Auth 可按运维策略作为额外纵深防护。
2. **上传大文件优化**：结构文件/数据集 >50 MB 时走对象存储（COS 直传）减轻隧道压力。
3. **多服务接入**：同一 frps 加代理即可再暴露本地其它 HTTP 服务（按域名分流）。
4. **更严格访问**：Nginx `allow/deny` 限定来源 IP 段（如校园出口段）或启用 fail2ban 封禁。
